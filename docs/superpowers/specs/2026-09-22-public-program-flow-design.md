# 외부 공개용 프로그램 흐름 및 온라인 평가 설계

## 목표

외부 공개 페이지의 프로그램 흐름을 `온라인 모집`에서 시작하도록 정리하고, 온라인 평가에서 지원자가 제출할 자료를 명확히 안내한다. 일정·프로그램 문구·제출 형식·작성 예시는 하나의 Markdown 기준 문서에서 관리하며, 상세형과 홍보형 포스터가 같은 내용을 사용하도록 한다.

## 공개 흐름

공개 순서는 다음과 같다.

`온라인 모집 → 온라인 평가(아이디어 제출) → 참가자 발표 → 현장 해커톤 → 인턴 선발·멘토 배정 → 사전학습 → Winter Research Internship`

기존 내부 단계인 “공고 확정·홍보 준비”는 외부 공개 흐름에서 제거한다. 공고 확정 전 안내가 필요한 경우에는 포스터 상단의 초안 안내문으로만 표시한다.

## 온라인 평가 제출 형식

지원자는 다음 두 파일을 제출한다.

1. **아이디어 1장**: PNG/JPG 또는 1페이지 PDF. 문제 상황, 제안 경험, AR/XR의 역할, 기대 효과가 한눈에 보이는 콘셉트 보드다.
2. **요약문**: Markdown 또는 폼 입력란에 300자 안팎으로 작성한다. 문제 정의, 대상 사용자, 핵심 상호작용, 구현 가능성을 간결하게 설명한다.

한 장 이미지는 시각적 사고와 문제 구조화를 보기 위한 자료이며, 완성도 높은 그래픽 디자인을 요구하지 않는다. 요약문은 이미지에 담기지 않는 연구 의도와 실행 계획을 확인하는 용도다.

## 평가 기준

온라인 평가는 문제 이해, 사용자와 상황의 구체성, AR/XR 활용의 적합성, 독창성, 실현 가능성을 중심으로 본다. 하드웨어 사양이나 그래픽 완성도보다 대화 상황에서 어떤 도움을 언제 제공하는지가 중요하다.

## 기준 문서와 산출물

- `content/program.md`: 공개 일정, 단계명, 설명, 온라인 평가 제출 형식, 평가 기준, 포스터용 요약 문구를 관리한다.
- `content/online-evaluation-submission-example.md`: 지원자가 복사해 사용할 제출 템플릿과 작성 예시를 제공한다.
- `scripts/build_public.py`: 기준 Markdown을 읽어 상세형(`docs/index.html`)과 홍보형(`docs/teaser.html`)에 공통 흐름과 문구를 반영한다.
- `index.html`, `teaser.html`: 로컬 편집용 원본. 기준 문서에서 가져온 공개 문구를 표시한다.
- `docs/index.html`, `docs/teaser.html`: 빌드된 읽기 전용 공개 포스터.

## 예시 아이디어

예시 제목은 “처음 만난 사람과의 대화를 돕는 AI 글래스”로 한다. 한 장 이미지에는 두 사람이 대화하는 장면, 낯선 개념을 짧게 보여주는 시각 카드, 질문 타이밍을 돕는 인터랙션을 배치한다. 요약문은 청각 정보가 부족하거나 전문 용어가 낯선 상황에서 상대방의 설명을 방해하지 않고 핵심 정보와 시각 단서를 제공한다는 내용을 300자 안팎으로 설명한다.

## 성공 조건

- 두 공개 포스터의 첫 단계가 모두 `온라인 모집`이다.
- 온라인 평가가 아이디어 이미지 1장과 요약문 제출로 명시된다.
- 제출 템플릿과 완성 예시가 별도 Markdown 파일로 열람 가능하다.
- 일정과 문구를 `content/program.md`에서 수정한 뒤 빌드하면 두 포스터에 같은 내용이 반영된다.
- 빌드 결과에는 편집 도구와 내부 운영 검토 패널이 포함되지 않는다.
